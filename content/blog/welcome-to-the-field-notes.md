## Why this exists

This blog records how I reach security conclusions, not only where I land. I will document the sources I trust, the assumptions I make, the tools I build, and the evidence that changes my mind.

Topics will span **vulnerability intelligence**, threat hunting, detection engineering, governance, and the systems connecting them. Some posts will explain a shipped tool; others will preserve a method, experiment, or failure worth repeating.

## What I will publish

- Research methods and source evaluation
- Engineering decisions and trade-offs behind public projects
- Reproducible notes on detection, vulnerability triage, and [MITRE ATT&CK](https://attack.mitre.org/)
- Corrections when new evidence changes an earlier conclusion

> A conclusion is useful only when someone else can inspect the evidence behind it.

My default workflow is deliberately simple:

```text
question -> sources -> observations -> analysis -> confidence -> revision
```

Each post should separate observation from inference, link material sources, state uncertainty, and update the record when evidence changes.
